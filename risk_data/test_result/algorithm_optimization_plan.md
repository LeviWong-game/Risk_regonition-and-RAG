# 风险预测算法优化方案

生成依据：`metrics.json`、`confusion_matrix.csv`、`error_cases.jsonl`  
当前测试集：`risk_val_clean.jsonl`，共 26 条验证样本  
当前算法入口：`risk_scoring.assess_case`

## 1. 当前效果概览

本次测试中，规则风险预测算法的总体准确率为 `0.6538`，Weighted F1 为 `0.6506`，风险分数区间命中率为 `0.6538`。从混淆矩阵看，算法可以识别多数 L2 样本，但对 L1 和 L3 的边界把握仍不稳定。

主要指标如下：

| 指标 | 当前结果 |
| --- | --- |
| 样本数 | 26 |
| 正确样本 | 17 |
| 错误样本 | 9 |
| Accuracy | 0.6538 |
| Weighted Precision | 0.7180 |
| Weighted Recall | 0.6538 |
| Weighted F1 | 0.6506 |
| Score Range Hit Rate | 0.6538 |
| 分数到标注区间中点平均绝对误差 | 14.0962 |

分等级表现：

| 等级 | 样本数 | Precision | Recall | F1 | 主要问题 |
| --- | ---: | ---: | ---: | ---: | --- |
| L1 | 7 | 1.0000 | 0.4286 | 0.6000 | 低风险样本容易被抬高到 L2/L3 |
| L2 | 13 | 0.6667 | 0.7692 | 0.7143 | 部分一般风险被抬高到 L3 |
| L3 | 6 | 0.5000 | 0.6667 | 0.5714 | L3 预测偏宽，误收了部分 L1/L2 |
| L4 | 0 | 0.0000 | 0.0000 | 0.0000 | 验证集中无 L4，无法评估 |

## 2. 主要问题诊断

### 2.1 整体存在高估倾向

9 个错误样本中有 7 个是高估，2 个是低估。主要误判对为：

| 误判对 | 数量 | 含义 |
| --- | ---: | --- |
| L2 -> L3 | 3 | 一般风险被判为较高风险 |
| L1 -> L2 | 3 | 低风险被判为一般风险 |
| L1 -> L3 | 1 | 低风险被明显高估 |
| L3 -> L2 | 2 | 较高风险被低估 |

这说明当前规则对部分关键词、案件类型先验、影响范围和公共秩序指标的加分偏强，容易把没有明显升级信号的案件推高一级。

### 2.2 L1 召回率偏低

L1 的 Precision 为 1.0，但 Recall 只有 0.4286。也就是说，只要算法预测为 L1 通常是对的，但很多真实 L1 没有被识别出来，而是被预测为 L2 或 L3。

典型原因：

- 案件类型先验对邻里纠纷、物业纠纷等常见类型给了基础风险加成。
- 文本中出现“住户”“小区”“业主”等词时，影响范围或公共秩序指标容易被抬高。
- 轻微纠纷缺少“降权规则”，导致算法只看到风险词，没有识别“单一主体、无升级、可自行处置”的低风险特征。

### 2.3 L3 精确率偏低

L3 的 Precision 为 0.5，说明预测为 L3 的样本中有一半并不是真实 L3。错误样本中 L2 -> L3 有 3 条，L1 -> L3 有 1 条。

典型原因：

- “报警”“威胁”“泼水”“污染”“多次投诉”等词触发较高冲突或影响分。
- 部分词在真实场景中可能只是描述事件存在争议，并不一定代表风险已达到 L3。
- 当前分数阈值或校准参数使得边界样本容易越过 L3 下限。

### 2.4 L4 缺少验证覆盖

验证集中 L4 样本数为 0，因此无法判断算法对高风险、极端风险场景的识别能力。当前结果不能证明 L4 规则有效，也不能证明 L4 没有误报风险。

## 3. 优化目标

建议按两阶段推进，先做规则校准，再做数据补强。

短期目标：

| 指标 | 当前值 | 目标值 |
| --- | ---: | ---: |
| Accuracy | 0.6538 | >= 0.75 |
| Weighted F1 | 0.6506 | >= 0.72 |
| Score Range Hit Rate | 0.6538 | >= 0.75 |
| L1 Recall | 0.4286 | >= 0.65 |
| L3 Precision | 0.5000 | >= 0.65 |

中期目标：

- 补充 L4 验证样本后，L4 Recall 不低于 0.70。
- 分数到标注区间中点平均绝对误差从 14.0962 降到 10 以内。
- 高估样本占错误样本比例明显下降，避免基层处置资源被过度占用。

## 4. 具体优化措施

### 4.1 增加低风险降权规则

目的：提高 L1 召回率，减少 L1 -> L2 和 L1 -> L3。

建议在评分后处理阶段增加“低风险保护”逻辑。当案件同时满足以下特征时，限制最高等级不超过 L1 或 L2：

- 无触发规则：`trigger_flags` 为空。
- 无人身伤害、群体聚集、舆情扩散、司法/公安介入等强升级信号。
- 纠纷主体较少，文本仅描述单户、两户、个别住户、个别业主。
- 处置难度低，未出现“多部门”“法院”“公安”“信访”“应急处置”等词。
- 分数刚进入 L2 或 L3 边界，但主要来源是案件类型先验或弱关键词。

建议优先处理以下误判样本模式：

- 物业服务不到位、拒缴物业费、物业费上涨但无群体性行动。
- 楼上楼下影响生活但无伤害、无持续升级。
- 邻里边界或噪音纠纷中，已经由社区或调解员介入但未出现聚集、舆情、伤害。

### 4.2 调整案件类型先验权重

目的：降低案件类型本身对风险等级的过强影响。

当前部分错误样本的原因文本中显示，物业纠纷、邻里纠纷、环境污染等类型先验会抬高冲突强度、影响范围、公共秩序或跨部门协调难度。建议：

- 当文本没有命中明确风险关键词时，案件类型先验只作为轻微补充，不应单独把样本推高到 L2 或 L3。
- 对物业纠纷、邻里纠纷的 `impact_scope`、`public_order_opinion`、`cross_department_difficulty` 先验下调一级或降低融合权重。
- 对“消费维权”“矛盾调解”等未在先验字典中充分覆盖的类型，增加更保守的默认先验，避免被通用关键词误伤。

### 4.3 细化关键词强度

目的：减少弱风险词直接触发高分。

建议把关键词分为三类：

| 类别 | 处理方式 | 示例 |
| --- | --- | --- |
| 强风险词 | 可直接抬高等级或触发下限 | 聚集、堵路、持刀、重伤、法院介入、公安介入 |
| 中风险词 | 需要与持续性、影响范围、处置难度组合后才升级 | 多次投诉、威胁、报警、污染、拖欠 |
| 弱风险词 | 只给轻微加分，不单独导致 L3 | 小区、住户、业主、投诉、不满、争议 |

对本次错误样本中出现的“报警”“威胁”“泼水”“小区”“住户”“业主”“多次投诉”等词，建议检查是否存在单词命中即赋高分的问题。中风险词应至少满足两个以上维度共同命中，才允许进入 L3。

### 4.4 增加 L2/L3 边界校准

目的：降低 L2 -> L3 误判。

建议在最终等级判定前增加边界校准：

- 当预测分数处于 L3 下限附近，且没有红旗触发规则时，要求至少满足一个强升级条件才判为 L3。
- 如果 L3 的依据主要来自 P 或 I 单一维度，而 D 维度很低，可将等级回退到 L2。
- 对 53-65 之间的边界分数增加复核逻辑，判断是否存在“持续恶化、群体影响、严重伤害、多部门处置”之一。

本次 L2 -> L3 错误样本的预测分数为 59、62、69，说明 L3 边界附近和中段都需要校准。

### 4.5 增强低估场景识别

目的：修复 L3 -> L2 的低估样本。

本次有 2 条 L3 被低估为 L2，主要集中在物业管理和环境污染类场景。建议增加以下识别能力：

- 对“电梯停运多日/多周、影响居民出行、公共设施长期不可用”提高影响范围和处置压力评分。
- 对“工厂排放超标、影响居民健康”提高安全健康损害评分，并在健康影响明确时允许进入 L3。
- 对“流程复杂导致长期拖延”增加处置难度评分，而不是仅依赖是否出现多部门关键词。

### 4.6 补充高风险样本

目的：验证和优化 L4。

当前验证集没有 L4，建议补充不少于 20 条 L4 样本，覆盖：

- 人身伤害、持械、重伤、死亡威胁。
- 群体聚集、堵路、冲击办公场所。
- 重大安全隐患，如火灾、爆炸、燃气泄漏、坍塌。
- 公安、法院、信访、媒体舆情已介入。
- 多部门应急处置或跨区域影响。

同时补充与 L4 相似但实际为 L3 的边界样本，避免算法只要看到强词就全部判为 L4。

## 5. 推荐实施顺序

第一阶段：规则校准，预计 1-2 天。

1. 增加低风险保护逻辑，优先降低 L1 -> L2/L3。
2. 调整案件类型先验权重，减少物业、邻里、环境类弱文本高估。
3. 增加 L2/L3 边界复核逻辑。
4. 复跑 `run_algorithm_test.py`，比较 Accuracy、L1 Recall、L3 Precision、Score Range Hit Rate。

第二阶段：样本补强，预计 2-4 天。

1. 补充 L4 样本和 L3/L4 边界样本。
2. 补充 L1 轻微纠纷样本，尤其是物业、邻里、消费维权类。
3. 重新生成训练/验证集，并保持验证集类别分布相对均衡。
4. 复跑算法测试，更新报告。

第三阶段：模型化评估，预计 3-5 天。

1. 如果后续接入微调模型，将规则引擎作为 baseline。
2. 使用同一验证集比较规则算法、模型算法、规则+模型融合方案。
3. 固定输出同一套指标：Accuracy、Macro F1、Weighted F1、Score Range Hit Rate、混淆矩阵和错误样本。

## 6. 复测标准

每次优化后都应运行：

```bash
python risk_data/run_algorithm_test.py
```

复测时重点观察：

- `metrics.json` 中 Accuracy 是否提升到 0.75 以上。
- L1 Recall 是否提升，且 L1 Precision 不出现明显下降。
- L3 Precision 是否提升，减少 L1/L2 被误判为 L3。
- Score Range Hit Rate 是否提升，说明分数校准更加贴近标注区间。
- `error_cases.jsonl` 中高估样本数量是否下降。
- 新增 L4 验证样本后，L4 的 Recall 和 Precision 是否达到可接受水平。

## 7. 风险与注意事项

- 不建议只为了提高当前 26 条验证集准确率而硬编码样本特征，应优先调整通用规则。
- 当前验证集规模较小，单个样本会明显影响指标，因此优化后需要扩大验证集再判断稳定性。
- 降低高估倾向时要防止漏判真实高风险场景，特别是人身伤害、群体聚集、公共安全隐患和司法公安介入。
- 对 L4 的任何结论都需要补充样本后再确认，当前测试结果不能代表 L4 能力。

## 8. 预期优化结果

完成第一阶段后，预期可以达到：

- Accuracy 从 0.6538 提升到 0.75 左右。
- L1 Recall 从 0.4286 提升到 0.65 以上。
- L3 Precision 从 0.5000 提升到 0.65 以上。
- Score Range Hit Rate 从 0.6538 提升到 0.75 左右。
- 高估错误从 7 条下降到 3-4 条。

完成第二阶段后，指标应更稳定，并能开始评估 L4 高风险识别能力。
